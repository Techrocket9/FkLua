# Engine findings: what Factorio itself does that a mod cannot change

A list of engine behaviours measured on real binaries that a mod, a guest or this toolchain cannot work around, kept so that tickets can be opened on them some day with the evidence already gathered. Every entry names the binary it was measured on and the document that holds the command and the output; nothing here is argued from memory. Add an entry when a round finds one, and move it to the closing section if a later engine fixes it. Entries that are limits rather than defects are kept apart at the end, because a ticket asking for a limit to be documented is a different ticket from one asking for a crash to be fixed.

The evidence lives in three places: FkRecipes' `agents/customizer-design.md` (the probe mods and their tables), BetterBeltBalancer's `agents/migration-assessment.md` and `agents/migration-assessment-2.md` (the adversarial migration assessments, 2026-09-08 and 2026-09-13, each measurement with its command), and BetterBeltBalancer's `CLAUDE.md` where noted.

## Defects, most severe first

1. **A NaN stored in a double startup setting passes the range check, reaches the mod, and then aborts the engine after the data stage.** Measured on 2.0.77 (build 84539). The range check compares against minimum and maximum, and every comparison with NaN is false, so the value is accepted where an infinity is reset. The data stage completes and the mod handles the value, then the engine's own write-back self-check deserialises what it wrote, compares `NaN != NaN`, prints `Error GlobalModSettings.cpp:204: Before:` and `:215: After:` with byte-identical hex blocks (`cmp` exit 0), then `:217: Saving and loading changed data.` and `Error CrashHandler.cpp:643: Received 6`. The client shows the bare operating-system crash dialog with no mod name, no setting and no button that reaches anything, and the file is never rewritten, so every relaunch repeats it. The int setting rejects NaN at the same check, so the fix is one comparison. A player cannot type a NaN (the numeric widget filters it); a file written outside the game can. BBB `agents/migration-assessment-2.md`, finding 16.

2. **The mod-load error dialog cannot reach the Mod Settings screen.** Measured on the 2.0.77 client. The dialog offers `Disable listed mods`, `Disable all mods`, `Manage mods`, `Restart`, `Exit` and a `Reset mod settings` checkbox. `Manage mods` opens the Mods screen (Manage, Explore, Updates tabs; a list with enable checkboxes; Back and Confirm) with no Mod settings button, and `Back` returns to the same dialog. `Restart` relaunches into an identical dialog over a file whose sha256 has not moved, because the engine rewrites `mod-settings.dat` only on a successful load. A disabled mod's settings do not appear on the Mod Settings screen either. So a mod whose data stage refuses on a stored setting has locked the player out, and the only exit resets every startup setting of that mod and disables it. Any mod that validates a setting at the data stage meets this. BBB `agents/migration-assessment.md` finding 2 and `agents/migration-assessment-2.md` finding 14.

3. **A localised description that references one locale key nothing defines removes the whole setting tooltip and its info icon, silently.** Measured on the 2.0.77 client with a control: a startup dropdown whose composed `localised_description` names `technology-name.logistics-2`, which no shipped locale file defines, renders with no info icon and no tooltip while the five rows beside it have both; a three-line probe mod that defines only that key restores the icon, and removing the probe takes it away again. The engine's own `mod-settings-dump.json` says the description is present, exit 0, no warning anywhere, so no headless check can see it. Elsewhere the engine renders a missing key as the raw key text; the settings tooltip drops everything instead. The same happens to a RECIPE's `localised_description`: an undefined key anywhere in the composition drops the whole description block from the crafting tooltip while the title, ingredients and time survive, with no "Unknown key" text, exit 0, and the description present verbatim in the dump. The `{"?", alt1, alt2}` form is the workaround: an undefined key counts as a failed alternative and the next one renders, measured on the same client with controls side by side. BBB `agents/migration-assessment-2.md`, finding 15; the probe report at the FkRecipes operator's briefs directory, `probe-client-report.md` (2026-09-13).

4. **A NUL inside a stored string setting of fewer than 22 bytes is cut at the NUL before the mod sees it, and a successful load persists the cut with no log line.** Measured on 2.0.77 with a sweep at 21, 22, 23 and 24 stored bytes: at 21 and 22 the guest receives the prefix and the rewritten file holds the prefix; at 23 and 24 the NUL reaches the guest intact and the file is untouched. The boundary is the small-string optimisation's, and a player's text does not survive for them to fix. Separately, the engine cuts a mod's LOAD-FAILURE MESSAGE at a NUL and prints only what precedes it (a 37-byte message came out as its first 20 bytes inside the engine's 56-byte frame). FkRecipes `agents/customizer-design.md`, the NUL row and the paragraph under it; BBB `agents/migration-assessment-2.md`, finding 10.

5. **A stored dropdown value outside `allowed_values`, and a stored number outside its range, are reset to the default before any stage runs, with no log line, and the reset is persisted.** Measured on 2.0.77 in both assessments. The mod never sees the value, so it cannot log the loss, and the player has no signal. The same mechanism means a release that adds a dropdown value destroys that choice on any machine that runs an older release once (a rollback, a modpack pin, a second machine), while every setting the older release does not declare survives verbatim. A wrong-TYPE value is also reset to the default but that one does log (`Error StringSetting.cpp:71: Failed to load mod mod setting (...): Value must be a string in property tree ...`), which is the behaviour the other two should have. FkRecipes `agents/customizer-design.md` measured tables; BBB `agents/migration-assessment-2.md`, finding 3 and "Hostile and accidental bytes".

6. **A fluid ingredient amount above DBL_MAX / 2^24 aborts the engine at the data stage.** Measured on 2.0.77: bracketed at 1.0715e301 loads and 1.0716e301 aborts with SIGABRT, the exact boundary being 1.0715086071862672e301. A prototype-validation refusal with a message is what every other out-of-range amount gets. FkRecipes `agents/customizer-design.md`.

7. **Changing a recipe's ingredients destroys every stack in an assembling machine's input inventory that is not an ingredient of the new list.** Measured on 2.0.77 across 37 loads: not spilled on the ground (`world.item-on-ground` empty every time), not moved to the output slot or a character, no log line; 80 items gone in the worst case. The rule is per stack, keyed on "not an ingredient of the NEW list"; `crafting_progress`, `products_finished` and the output slot survive. A chest survives a recipe change but not the removal of an item prototype, which destroys its stacks too while the placed entities of that item stand uncraftable. Possibly intended; the ask is a spill or a log line. BBB `agents/migration-assessment.md` finding 8 and `agents/migration-assessment-2.md` finding 8.

8. **`--benchmark-verbose` crashes with SIGSEGV on 2.1.16 after emitting the `t0` row, with any counter list, on a vanilla no-mod save as the control.** It works on 2.0.77. BBB `CLAUDE.md`, the benchmark section (search for `--benchmark-verbose`).

9. **Invalid UTF-8 and control characters in a stored string setting reach the mod untouched.** Measured on 2.0.77 in the probe mods: a mod cannot rely on a string setting being text, and must validate bytes it did not write. Recorded here because a ticket asking for the settings file to be validated at load would cover entries 4, 5 and 9 together. FkRecipes `agents/customizer-design.md`.

## By design, recorded so nobody files it twice

- A mod that loads after another can delete or rewrite the earlier mod's prototypes at `data-updates` or `data-final-fixes`, and the earlier mod sees nothing: the staging model is the engine's and the only defence is a check at final-fixes. BBB `agents/migration-assessment-2.md`, finding 17.
- The settings screen is a flat list with no conditional visibility: a setting whose value the mod is ignoring renders exactly as one in force, and the prototype carries no state a mod could set. The whole customizer design in FkRecipes rests on this; `agents/customizer-design.md` records the probe.
- The settings stage sees an empty `data.raw`, so no picker over the game's items can exist at that stage. Same record.

## Limits measured, not defects

- A localised string takes at most 20 PARAMETERS PER TABLE (`Too many parameters for localised string: 21 > 20 (limit)`, literal and table parameters counted alike) and 20 LEVELS OF NESTING DEPTH (`Too deep recursion for localised string: 21 > 20 (limit)`), with NO global table count: a description holding 421 tables at depth 3 loads. A `?` wrapper costs one depth level and one parameter slot. Measured 2026-09-13 on 2.0.77 with a sweep; this corrects an earlier reading of "19 nested tables". The recipe prototype has the same parameter ceiling under its own message (`Error while loading recipe prototype "..." (recipe): Too many parameters for localised string: 21 > 20 (limit)`).
- Item ingredient amounts are 1 to 65535 and a fraction loads as written; a research unit takes `tool` items only, an empty unit loads, time and count must be positive. Same record.
- Prototype names take `A-Z a-z 0-9 _-`, at most 200 characters; a 2401-character string default loads. Same record.
- Lua's jump limit, the 18-bit span, is the ceiling every generated module meets first; `docs/lua-limits.md` here is the account.
- `player.opened = defines.gui_type.controller` is accepted without error and draws nothing (the screen dims, no GUI appears); `player.opened_self = true` is refused with `LuaPlayer::opened_self is read only.`; `player.opened = player.character` is what opens the character screen. Measured 2026-09-13 on 2.0.77 while driving the probe above.
