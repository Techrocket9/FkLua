# The library ecosystem — decisions, rules, and the record behind them

Research record, 2026-08-30: three rounds of deep dives (in-repo constraint mapping, hands-on toolchain probes, external prior art) plus a coupling map for fkipc, a module-by-module flib study, a requirements pass for the first net-new library, and a toolkit-injection survey. This file carries the decisions and the numbers that made them, so they are not re-derived. The small enablers it produced shipped the same day (env(4)/env(5), the settings-dump gate hash, the round-trip closure); the major items are listed at the end.

## The model: same-language SOURCE libraries, compiled into the consumer's wasm

A library is a Go package / Rust crate the consumer's guest imports — the shape `fklog`, `fkipc`, `fkdata` already have. This is not a compromise: Factorio's own library ecosystem (flib, via cross-mod `require`) is already "one copy per consumer, no shared state, resolved at load time", because every mod's control stage runs in its own Lua state. A statically linked library reproduces flib's observable semantics exactly.

**In-module cross-language is ruled out, and the reason is not that it cannot be built — it is that it links TODAY and is silently unsound.** Measured on this machine: a Rust `staticlib` links into a TinyGo `wasm-unknown` guest with one `#cgo LDFLAGS:` line, ships through `fklua mod`, runs — and both runtimes claim `[__heap_base, ∞)`, so TinyGo's allocator destroyed **99,712 of 100,000 bytes** of a live Rust heap block with no trap; under `--gc=collected` fkgc grew straight through a live Rust block (50,000/50,000) and swept over it; `wasm-merge --multi-memory-lowering` produced a single-memory module `fklua compile` ACCEPTS in which Go's heap overwrote Rust's `.rodata` (476/628 constant bytes). TinyGo's own fix (exported `malloc`/`free` over the Go allocator) is build-tagged off for exactly the `wasm_unknown` target. The only sound linked shape is a Rust library that never allocates — statics and caller buffers only — which is not an authoring model. Every surveyed plugin ecosystem (Extism, proxy-wasm, Shopify, Zellij, WASM-4, Minecraft) ships per-language SDKs and puts cross-language reuse in the host or behind a message boundary; the one real cross-language answer, the wasm component model, is shared-nothing — N modules, N memories, canonical-ABI copies at every library call — i.e. the `read_dyn` cost this project spent milestones removing at HOST-call frequency, reintroduced at library-call frequency, on Go tooling that is pre-1.0 and mid-rewrite.

**Cross-language reuse is served, at the right boundary: the cross-mod seam.** `fk.register`/`fk.remote_call`/mod-defined events are cross-language by construction and priced honestly (a host call is ~12.5 µs plus tier-2). A service mod is the pattern for shared STATE; a source library is the pattern for shared CODE. That split is forced by state, not taste, and every ecosystem surveyed converged on it.

## The two library classes, and the pin

- **Pin-transparent**: depends on `fk` alone (fklog) or `fkdata` alone (a data-stage library). Cannot be broken by a pin move; outside `fklua lock`, the stamps and the census entirely. **The asymmetry to know**: Rust's tier-2 marshalling lives in hand-written `fk`, Go's in generated `fkapi` — so "fk-only" is cheaper to honour in Rust, and pin-transparent Go libraries that speak tier-2 would need marshalling moved into Go's `fk`.
- **Pin-coupled**: imports the generated `fkapi` (fkipc, a future translation-dictionary library). Must use the CONSUMER's binding set, never vendor its own — two binding sets in one module are refused (`checkAPIPin`), which is protobuf's "centralize, never vendor" rule with a stronger digest. The consumer's `replace` (Go) / `[patch]` (cargo) onto a vendored checkout plus `gen-bindings --into` is the supported flow, and the stamps turn a mismatch into a package-time refusal.

## Rules a library author faces (the enforced ones and the doc-only ones)

Compiler/refusal-enforced: no second `#[global_allocator]`/`#[panic_handler]`; no export of any `factorio.Hooks` name (route through the author's exports — `OnEvent(id, ptr) bool` is the convention); no wasm import outside `fk`/`env`/`wasi_snapshot_preview1`; no vendored `fkapi`; data libraries must not touch `fkapi` (`CheckDataModule`). Doc-only, and therefore the future lint surface: `#[inline(always)]` on every wrapper carrying a member/event/define id (R6 — a wrapper that stops inlining silently ships the full tables, ~55 KB–1 MB per load, one build-output line as the only tell); register commands/interfaces from `init()`; `fk_alloc_static` for anything cached across calls; never store an outbound call's outcome or anything computed under a load hook (fkipc's two shipped violations are the case study); never iterate a hash map to decide what to write. Rules with no home yet, recorded here: **never give `fkapi` a Go `/v2` path suffix** (module paths with major suffixes are DIFFERENT packages to Go — both copies would link, the two-binding-sets bug with no refusal); **Cargo feature unification means the CONSUMER's graph decides `fk/fkgc`** — a library must not declare the feature and cannot rely on its absence; **one source for the `fk` crate** — a consumer path-dep plus a library git-dep is two crates and a duplicate-allocator link error, so the `[patch."https://github.com/Techrocket9/fklua"]` convention (or publishing `fk`) is load-bearing for Rust.

## Distribution status

**The Go channel is LIVE: `guest/go/v0.1.0` is tagged and pushed (2026-08-31)**, so `go get github.com/Techrocket9/fklua/guest/go@v0.1.0` resolves to a real version; the sdk's go.mod header prescribed exactly this. **The Rust convention is DECIDED (2026-08-31): a git dependency plus the `[patch]` one-source rule, and NO crates.io publishing.** The reasoning: the pin-coupled half (`fkapi`) can never be published — it is generated per pin — so publishing `fk` alone would split the Rust story into two channels where git+`[patch]` is one; the author meets the convention where it bites, in `init --library`'s generated Cargo.toml and the toolkit's repin page. Revisit only if a published-crate consumer materialises with a need `[patch]` cannot express. At the default pin, both library classes are near-native DX; at a custom pin, the vendor flow. The one genuinely unsolved problem: **repinning a pin-coupled library through a package-manager cache** — `gen-bindings --into` targets a writable FkLua-checkout layout, and Go's module cache and cargo's git checkouts are read-only. That design round is deliberately deferred until the first external pin-coupled library needs it.

## Verdicts

- **fkipc: stay in-repo, tag `guest/go`. Do not split.** Zero fkipc source commits in the 74 since the squash point (the moving edge is `fkapi`, its dependency — the wrong direction for a split to help); a split severs the wire-parity gate (needs the compiler + oracle), strips `TestAJoiningPeerStaysByteIdenticalToTheServer` of its only join-traffic corpus, and breaks `lib-engine.sh`'s single-spelling floor read. And fkipc is the HARDEST library case (the pin-coupled one), not the representative one — it belongs here as the reference case until the repin mechanism exists. "Split out" and "independently distributable" are separable; only the second has a customer, and it costs one tag.
- **flib: port a small subset; never a shim.** `fk.remote_call` decodes through `read_dyn` (the measured 86% of a host call) before `remote.call` even copies, so a shim traverses a payload four times where native traverses twice — the strictly better batching design was already measured at 0.868× and refused. Of flib's 2,024 code lines in 21 modules, 16 modules are stdlib/thin wrappers, 3 are data-stage, `migration` is gone upstream, and exactly ONE is service-shaped: `dictionary`, whose shimmed form is ~625× worse on the lookup it exists for and whose native port (~300 lines, every primitive bound) is the eventual `fkdict`. The free slice (styles/sprites/locale via a dependency line) is documented in `docs/from-lua.md`. The stdlib-equivalent modules are deliberately NOT ported (array/table/math/queue, on-tick-n, reverse-defines, direction/orientation, train, gui-templates); geometry/format helpers are on-demand only, and become pin-coupled if built over `fkapi`'s generated structs.
- **First net-new library: user-configurable recipes and research.** Data-stage-pure, `fkdata`-only, pin-transparent — the ideal opener. Shape: FDSL's recipe/technology verb set + a settings-generation layer + a prerequisite-cycle validator (the engine's own cycle diagnostic is eight words with no attribution; every dangling name is a hard load failure blaming the consumer — measured, so prove-present-before-naming and the validator ARE the product). BBB's `guest/go/tune` is the hand-rolled prototype and its design rule transfers whole: cost and tree position are ONE choice ("the prerequisite moves with the unit"). The enablers it needed shipped 2026-08-30: the mod's own name through `env(4)` (same-type setting collisions are silent last-writer-wins, measured), `defines.prototypes` through `env(5)`, the settings-dump hash in the gate, and the settings→data round trip proven in game. Known residuals: dropdown-value localisation has no inline mechanism (the one place a locale story is unavoidable), and 32 of 275 base technologies are `research_trigger` (no `unit` at all — read the whole `unit` map and check its tag).

## Roads not taken, with their numbers

- **A string-encoded batch shim** is the only shim arithmetic that works (a 2 KB serialized spec crosses ~28 µs against ~885 µs as a tier-2 tree) — and it is a bespoke wire protocol with flib nowhere in it. Recorded so it is not rediscovered as a flib idea.
- **A `[control]` require chain** (author Lua at an FkLua mod's control stage) does not exist; the blocker is real — `ModGlue()` owns event registration and `storage`, and author Lua on either side of it opens the two-registrars seam this project has so far been able to say does not exist. Same-state `remote.call` would still deep-copy and still refuse closures, so it would buy an escape hatch, not a flib bridge.
- **A mixed-toolchain tripwire** in `fklua compile` is worth considering: the cgo-linked module and the multi-memory-lowered merge both compile today and are silently corrupt; the `target_features` union (a linked module gains `+bulk-memory +reference-types` from Rust's rlibs regardless of RUSTFLAGS) is a possible tell.

## The toolkit's half (fklua-mod-toolkit), and the asks pointed back here

The toolkit survey ranked its own work (repin flow, data-module build, status view, `lib add`) — that lives in the toolkit's planning. Two asks land ON THIS REPO: **`fklua mod --report PATH` (JSON)** — the pruning verdicts, pin/ABI-signature outcomes, gc checks and wired hooks as a machine surface, because they are all stderr/stdout prose today and every diagnostics feature over there is blocked on it (the `api diff --json`/`bench --json` precedent applies); and **`fklua init --library`** — a library scaffold with the composition contract baked in, fklua-side so the layout cannot drift from `init`'s own constants. A third, softer ask: publish the two-language mirror harness recipe, or third-party dual-language libraries will drift the way `rustgen` did.
